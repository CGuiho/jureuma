# Human Review — 0.3.1 Picker Fix (2026-10-18)

## Verdict

**Accepted and released.** CG reported that pressing Enter in the `init`
stored-key picker re-prompted for a number, and instructed: “Change this and
bump patch.” The fix was delivered, reviewed, and published as the 0.3.1
patch release.

## What was built and verified

- Enter (an empty line) now selects the synthetic `create a new key` default
  immediately; EOF still cancels; numbers, full/short key IDs, garbage
  re-prompts and the non-TTY refusal are unchanged.
- The synthetic entry renders as `create a new key (default)` — no empty
  key-ID/public-key columns and no `active` state — and the prompt names the
  default.
- Commits `df103b5` (picker and tests) and `84a336a` (CHANGELOG, ledger
  Q40/Q41); parent re-ran `ci-check` and `test-e2e`, both exit 0.
- Release: `bfae325` prepared 0.3.1 (version-synced examples and agent
  artifacts), Mirror tagged and pushed `v0.3.1`, `release-prepare` produced the
  artifact set, `release-verify: 0.3.1 ok (22 files)`, and
  [jureuma 0.3.1](https://github.com/CGuiho/jureuma/releases/tag/v0.3.1) was
  published with 23 assets (not draft, not prerelease); `schema-publish`
  completed.
- Readbacks: the downloaded `jureuma-linux-amd64` reports `0.3.1` and matches
  `checksums.txt`; the release is the repository’s latest.

## Follow-ups

None from this fix. The 0.3.0 residual follow-ups remain as recorded in the
