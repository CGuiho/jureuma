# Human Review — 0.3.0 Train (2026-10-18)

## Verdict

**Accepted and released.** CG reviewed the handoff packet and instructed
“release”. That instruction authorized the Mirror version decision for 0.3.0
(commit, tag, push) and the publication of the GitHub release and its assets.
The 0.3.0 train is complete; #10-#14 are closed and archived.

## What was reviewed

The packet [2026-10-17-0.3.0-train.md](../handoff/2026-10-17-0.3.0-train.md),
with its acceptance mapping, question-ledger digest, deviations, self-review

[0.3.0-train-review.md](../implementation/0.3.0-train-review.md) and
[0.3.0-train-validation.md](../../validation/0.3.0-train-validation.md).

## What was published and verified

- `mirror version plan 0.3.0` → tag `v0.3.0`, no file-version mutation (Go
  version lives in the tag).
- `runx run version-sync -- 0.3.0` → the two example schema URLs and the five
  shipped agent artifacts pin `v0.3.0`; `version-check` ok.
- Release preparation committed as `e8cc795`; `mirror version apply 0.3.0
  --yes` → `applied: true`, annotated tag `v0.3.0` pushed at `e8cc795`.
- `runx run release-prepare` → 6 payloads, 6 launchers, agent artifacts,
  schemas and examples; `release-verify: 0.3.0 ok (22 files)`.
- `runx run release-publish` → GitHub release
  [zeze 0.3.0](https://github.com/CGuiho/zeze/releases/tag/v0.3.0),
  published (not draft, not prerelease), **23 assets**.
- `runx run schema-publish` → both schema assets present and pinned to
  `v0.3.0`.
- Readbacks: downloaded `zeze-linux-amd64` reports `0.3.0` and matches
  `checksums.txt`; the two schema URLs resolve on the release.

## Residuals accepted as shipped

The handoff listed six open points. None blocked the release; these remain the
recorded follow-up options:

1. Malformed `$zeze` headers are fixed by hand (no lenient repair reader).
2. Schema rename is explicit through `zeze.yaml` / `schema infer`.
3. Rotation is not cross-file transactional; re-run `key rotate` after a crash.
4. `.json` siblings are re-rendered canonically when their identity is
   refreshed; `.jsonc` is byte-spliced.
5. Windows runtime coverage is vet plus review only on this host.
6. Earlier open items: dogfooding the managed `AGENTS.md` block here, the B-6
   prompt-file naming, and Windows acceptance.

## Follow-ups

No follow-up issue was created from these residuals by this verdict; they stay
in the handoff packet until CG schedules them. The 0.1.0 verification items
(#4-#8) remain at Testing, unchanged.
