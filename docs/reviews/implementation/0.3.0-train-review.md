## Findings and fixes applied in-loop

1. **W2 contracts document carried a duplicated `WritePlain` line** — fixed in
   `d001550` during W2 acceptance.
2. **Design and CHANGELOG claimed “reads keep working” for malformed
   headers.** Format-1 reads work; malformed blocks are refused on read and
   reported (not repaired) by `init`. Corrected in `9fa662c`.
3. **Bound `key rotate` rekeyed one pair and updated the binding, leaving
   every other bound pair disagreeing and blocking even further rotation.**
   Fixed in `8e4a5f1`: project-wide rotation to one new key, all-or-nothing
   before the first write, one binding update, one retirement.
4. **`status`/`check` performed a keystore lookup with an empty key ID** on a
   plaintext-only headerless pair, exiting 5. Fixed in `8e4a5f1`: the report
   shows the state; `check` keeps its exit-1 repair pointer.
5. **Unbound both-present rotation left the plaintext `$zeze` identity on
   the old key**, after which `set`/`check`/`status` exited 5 with no CLI
   repair path. Reproduced by the parent, fixed in `b144d5a`; verified
   first-hand on the final tree.

## Residual risk (accepted, recorded, not redesigning)

- **Malformed `$zeze` blocks cannot be repaired by `init`** (Q20): they are
  refused on read and reported; a human must fix or remove the block. No data
  loss, but the repair pointer is two-step for this state. A lenient pair
  reader would be a separate `internal/pair` unit.
- **Rotation is not cross-file transactional.** A crash between pair-file
  writes can leave a pair disagreeing; a second `key rotate` re-keys both
  sides consistently (Q39).
- **`.json` siblings are re-rendered canonically** when their identity is
  refreshed; values, key order and `$schema` are preserved and
  zeze-written files round-trip unchanged. `.jsonc` is byte-spliced.
- **Schema-file rename is explicit** (Q21): the recorded `$zeze.schema`
  path is authoritative; a rename goes through `zeze.yaml` or
  `schema infer`.
- **Windows coverage is vet plus review only** on this host (`shellcheck` and
  `pwsh` absent); runtime Windows behavior was not executed.
- **`init` still creates an empty plaintext beside an only-encrypted pair**
  (pre-existing behavior, unchanged by this train); it is not a key-identity
  defect but may surprise in the single-file model.
