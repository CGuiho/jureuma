# Human Review — 0.3.0 Train (2026-10-17)

## What Was Built

- **#10 — `JUREUMA_CONFIG` restored as the default run env name.** The
  denylist exception follows it; `JUREUMA_` is refused as an ordinary
  `JUREUMA_*` name; every live surface (CLI help, schema, examples, README,
  root `AGENTS.md`, bundled skill/prompt/instruction, smoke) agrees.
- **#11 — OpenCode deny rules in `init`**, beside the Claude Code ones, with
  add/check/remove parity.
- **#12 — JSONC write support**, comment-preserving across `set`, `unset`,
  `decrypt` and `schema infer`; `.json` remains the default.
- **#13 — pair identity and single-file pairs.** Both files carry a
  `$jureuma` header (`format: 2`, `publicKey`, `keyId`, `home`); the plaintext
  always carries the `$schema` pointer; the encrypted file carries the schema
  document encrypted to the pair key. Legacy format-1 state refuses mutations
  with `run jureuma init to repair`; `init` repairs it keylessly and
  byte-idempotently. `set`/`unset` work with only the plaintext (keyless
  sibling rebuild), key selection uses the keystore labels (`key list`,
  `key show`, TTY picker, `--key-id`/`--key-label`), and `status`/`check`
  report all four pair states.
- **#14 — project key binding.** Optional top-level `key: <keyId>` in
  `jureuma.yaml`; every pair must agree (exit 5, never a silent re-encrypt);
  `init` uses it and splices it in one line without touching comments;
  `key rotate` is project-wide when bound (one new key, one binding update,
  one retirement, every recorded identity follows), and unbound rotation
  refreshes a headered plaintext sibling.

## How To Run And Test It

Build the binary (version `0.0.0-dev` until a release):

```sh
cd /root/swe/jureuma
runx run build            # or: sh devops/build.sh
```

Use a throwaway home and a scratch git project — **never** the real
`~/.guiho/jureuma/`:

```sh
export JUREUMA_USER_HOME=/tmp/opencode/review-home
export JUREUMA_NO_UPDATE_CHECK=1
mkdir -p "$JUREUMA_USER_HOME" /tmp/opencode/review-proj
cd /tmp/opencode/review-proj && git init -q
BIN=/root/swe/jureuma/bin/jureuma
```

1. **Fresh init and binding**
   ```sh
   "$BIN" init --agent-deny-rules no
   sed -n '1,20p' jureuma.yaml     # key: k_... spliced in, comments intact
   "$BIN" check                    # 0 failures
   ```
2. **Default env name**
   ```sh
   "$BIN" set /greeting --json '"hi"'
   "$BIN" run -- sh -c 'printf %s "$JUREUMA_CONFIG"'   # the document
   "$BIN" run --env-name JUREUMA_ -- true               # refused, exit 125 [JUREUMA:USAGE]
   ```
3. **Single-file flows**
   ```sh
   # with both files present, remove the encrypted side by hand to simulate decrypt
   mv config.encrypted.json /tmp/opencode/saved.enc.json
   printf '%s' 'new-value' | "$BIN" set /apiKey --value-stdin   # rebuilds the sibling, no key needed
   "$BIN" status                                               # encrypted-missing / rebuilt state
   ```
   Restore the saved file if you want the both-present state back.
4. **Legacy refusal and repair** (hand-made format-1 pair in another scratch
   project): a mutation refuses with `run jureuma init to repair`; `init`
   repairs it; a second `init` leaves it byte-identical.
5. **Rotation**
   ```sh
   "$BIN" key rotate        # project-wide when key: is set
   "$BIN" check             # 0 failures after rotation
   ```
   For the unbound case, remove the `key:` line, keep both files, rotate, and
   confirm `check`/`status`/`set` still exit 0.
6. **Human-only flows** (`decrypt`, `get`, `key show --private`) need a real
   terminal and the typed confirmation word — test them from your terminal,
   not from an agent session.

Full battery:

```sh
runx run ci-check
runx run test-e2e
```

## Question Ledger Digest

All entries: [2026-10-17-dnd-decisions.md](../../questions/key-identity-headers/2026-10-17-dnd-decisions.md).
Provisional answers, by theme:

- **Labels and listing (Q1-Q8):** short IDs in listings, labels default to the
  git origin repository name (directory fallback), `—` for no label, picker
  only on a TTY.
- **Headers and legacy state (Q9-Q14):** the legacy gate is pair-wide and keyed
  on format state, not header absence; headerless plaintexts stay mutable;
  refusals are exit 1 with typed sentinels; writes always render format 2;
  schema copy is `{ path, c }`; cross-file mismatch is exit 5.
- **Single-file flows (Q15-Q24):** keyless rebuild writes no baseline and never
  claims in-sync; `init` builds the sibling from the plaintext and repairs
  metadata only; malformed headers are reported, not guessed; the schema path
  is recorded (rename is explicit); `key rotate` migrates the schema copy;
  `decrypt` writes header + pointer and restores a missing schema.
- **Project binding (Q25-Q39):** multi-pair `init` converges on one project
  key; mixed-key projects get no binding; config field errors are exit 4; a
  mismatch maps to exit 5 (125 under `run`); project-wide rotation rotates
  every bound pair and skips identity-less pairs; the sibling identity follows
  in both rotation modes.
