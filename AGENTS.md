# AGENTS.md

Instructions for AI agents working in the `jureuma` repository.

## Project

`jureuma` is an **agent-safe configuration CLI** written in Go under the GUIHO conventions (`juju` is an optional alias installed by `jureuma juju-enable`). Agent-safe means AI agents can use jureuma to set configuration and secrets and inject them into processes without ever seeing plaintext values.

- Each configuration is a pair plus a schema: `<stem>.unencrypted.json` (plaintext, human-owned, always gitignored), `<stem>.encrypted.json` (every value encrypted with X25519, field names readable, committed) and `<stem>.schema.json` or `.schema.jsonc` (JSON Schema draft 2020-12, generated by `jureuma schema infer` and refined by agents, committed). The default stem is `config`.
- `jureuma run -- <cmd>` injects the whole decrypted document, JSON-stringified, into `JUREUMA_CONFIG` by default. `--format json|flatten|file` and `--env-name` change that. Child output is redacted.
- `decrypt`, `get`, `key show --private` and `key export` are human-only (terminal, no agent markers, typed confirmation word). `--dangerously-bypass-protections` is for humans who explicitly ask; it is audited.
- The CLI home is `~/.guiho/jureuma/`. Tests must set `JUREUMA_USER_HOME` (Go) or `HOME` (installer scripts) to a temporary directory and never touch the real home.
- Never put configuration values, plaintext or key material in any error message, log, test name or fixture output.

Behaviour is specified in [`docs/2026-10-13-jureuma-design.md`](docs/2026-10-13-jureuma-design.md). Package APIs are in [`docs/2026-10-13-jureuma-implementation-contracts.md`](docs/2026-10-13-jureuma-implementation-contracts.md). User documentation is in [`README.md`](README.md). The directory map is `xdocs tree`.

### Layout

- `cmd/jureuma`: `main` package; the version is injected with `-ldflags "-X main.version=<semver>"`.
- `internal/*`: one package per concern (cli, pair, runner, crypt, keystore, schema, config, gate, redact, jsonc, doc, paths, update, xerr, agentres).
- `test/e2e`: end-to-end tests against the built binary.
- `devops/`: `install.sh`, `install.ps1`, `uninstall.sh`, `uninstall.ps1`, and the build, release, smoke and lint scripts.
- `dist/` (release artifacts) and `bin/` (local builds) are gitignored build output.

### Everyday commands (all in `runx.yaml`)

```text
runx run jureuma-go-fmt-check      runx run jureuma-go-vet-cross      runx run jureuma-go-test
runx run jureuma-test-e2e          runx run jureuma-test-smoke        runx run jureuma-test-installers
runx run jureuma-build             runx run jureuma-release-prepare   runx run jureuma-ci-check
```

Releases: `mirror version plan <target>` (Git tags `v<semver>`; the first release is 0.1.0), then `runx run jureuma-version-sync -- <version>`. Apply, publish (`jureuma-release-publish`, `jureuma-schema-publish`), commit, tag and push only with explicit user authorization.

## Supported Format: JSONC

`jureuma` supports JSONC as defined by the [jsonc.org draft specification](https://jsonc.org/) (reference implementation: Microsoft `jsonc-parser`), in **lenient** mode:

- Base syntax is standard JSON (RFC 8259 / ECMA-404).
- `//` single-line and `/* */` multi-line comments are allowed wherever insignificant whitespace is allowed. Block comments do not nest. `#` comments are not supported.
- Trailing commas in objects and arrays are **accepted when reading** and **never emitted when writing**.
- Comments must not affect the data; removing them must yield the same values. When rewriting a file, preserve existing comments and formatting wherever possible.
- Preferred file extension is `.jsonc`; media type is `application/jsonc`.
- JSON5 features (unquoted keys, single quotes, hex numbers, `NaN`/`Infinity`, multiline strings) are out of scope.

## Technology Stack

- Go 1.26 and Cobra for the CLI. Go only: no TypeScript or TypeBox toolchain.
- Prefer the Go standard library; use native `go fmt`, `go vet`, `go test`, and `go build`.
- Resolve user paths with `os.UserHomeDir()` and `filepath.Join`; never assume Unix path syntax.

## Mandatory Project Tooling

The repository root must contain `mirror.yaml`, `runx.yaml`, and `xdocs.yaml`.

- **Mirror** is the sole authority for versions, changelog, release commits, and tags. Never edit version fields or create tags by hand. Run `mirror config check` and `mirror version plan <target>`; run `mirror version apply <target> --yes` only with explicit user authorization.
- **RunX** catalogs every supported project command in `runx.yaml` (build, test, vet, docs, schema generation, release prep, etc.). No workflow may exist only in a README, CI step, or shell history. Use `runx list` to discover operations and `runx run --dry-run <uid>` before mutating commands. After catalog changes run `runx check --format json` and `runx list --format json`.
- **XDocs** documents every project-owned directory with exactly one `*.xdocs.md` descriptor (no root `XDOCS.md` index; browse with `xdocs tree`). Update descriptors in the same work unit as the change. Validate with `xdocs meta <scope> --documents --strict`, `xdocs tree`, and `xdocs doctor <scope>`.

## Key CLI Rules (summary; the convention is authoritative)

- Flags: full long form only; the only short aliases are `-v` (`--version`) and `-h` (`--help`). Kebab-case names. Accept `--key value` and `--key=value`. List flags use Cobra `StringArray` with repeated flags, order preserved.
- `-v/--version` (top level only) prints the raw SemVer and nothing else.
- Every command supports `--help`, `--help-docs`, `--help-tree`, `--help-tree-depth`, `--help-tree-global-flags`.
- Required command tree: `init`, `agent {skill, instruction, prompt}`, `upgrade {check, list}`, `uninstall`. Never add an `install` command; never use the name `update`.
- Configuration: project `jureuma.yaml` and global `$HOME/.guiho/jureuma/jureuma.global.yaml`, each with its own JSON Schema and version-pinned schema reference. Include the `agent.evolution` policy (`disabled` | `always-ask` | `always-proceed`, default `always-ask`).
- Installation lives only in `devops/install.sh`, `devops/install.ps1`, `devops/uninstall.sh`, `devops/uninstall.ps1`, using a stable launcher in `$HOME/.guiho/bin/` and immutable payloads in `$HOME/.guiho/jureuma/versions/<version>/`.
- Never touch shared `$HOME/.guiho/`, `$HOME/.guiho/bin/`, `$HOME/.guiho/.temp/`, or another CLI's files.
- Bare `jureuma` invocation performs a cached, single-flight, non-blocking background update check.

## XDocs Structured Documentation

This project uses **xdocs** for structured, machine-readable documentation.
Load the `guiho-s-xdocs` agent skill when working with structured
documentation, `XDOCS.md` indexes, named `*.xdocs.md` descriptors,
companion documents, repository scanning, metadata discovery, or validation.
Use exactly one named descriptor per directory, such as
`technologies/technologies.xdocs.md`. The bare `.xdocs.md` and legacy
`.docs.md` names are invalid; the root `XDOCS.md` index is a special setup
file, not a second per-directory descriptor.

The project configuration is `xdocs.yaml`. Respect `ai.mode`:
`prompt` asks before already-authorized documentation writes, while
`auto` performs them immediately. Neither mode grants permission.
`documentation.directories` lists repository-relative directories whose
non-excluded subtrees may receive descriptor writes; `.` grants the whole
project and an empty list grants none. `documentation.frontmatter` contains
explicit `{pattern, kind}` rules for ordinary Markdown metadata, and those
rules work only inside an authorized directory. A legacy `ignore.rules` entry
with `frontmatter: false` always denies frontmatter and wins over an opt-in.
Keep ordinary Markdown listed in descriptor `documents` metadata without
adding headers unless both explicit grants match. Respect
`ignore.gitignore` and every `ignore.rules` entry.

Read-only `xdocs scan`, `xdocs meta`, `xdocs context`,
and `xdocs doctor` operations, plus `xdocs tree` without
`--output`, discover independently of the write allowlist. `xdocs tree` walks every non-excluded directory to arbitrary depth,
retains every named descriptor and the special root index, and reports malformed
or orphaned metadata without hiding paths. `meta --existing-frontmatter` and
`doctor --existing-frontmatter` audit existing ordinary Markdown headers
without requiring missing headers or writing repairs. `generate`,
`merge`, and `tree` print reports to stdout unless one exact
`--output` path is requested; that report path does not authorize any other
document writes and a generated report is never a descriptor.

The explicit `xdocs init` root-index creation and agent-resource bootstrap
are setup exceptions. They do not authorize arbitrary Markdown metadata edits.
